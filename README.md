# AutoML agent backend

Наша часть для хакатона Альфа: оркестрация LLM и Python-процессов, бюджеты,
контракт интеграции с ML-модулем, проверка и сохранение результата.
Модели, признаки, валидационные разбиения и ML-качество — зона тиммейта.

## Запуск на платформе

```sh
export OPENAI_API_KEY='...'
export OPENAI_BASE_URL='https://your-organizer-proxy/v1'
export OPENAI_MODEL='qwen/qwen3.8-27b'
python3 solution.py /data/task.md
```

Модель по умолчанию — `qwen/qwen3.8-27b`. Ключ и base URL обязательны.
Адрес выше — пример, используйте выданный организаторами. Решение ничего
не устанавливает при запуске. `requirements.txt` получен из материалов
организаторов; для платформы используется Python 3.12.

Успех: код выхода `0`, проверенный `submission.csv` рядом с `task.md`.
Код `1`: цикл завершён без зарегистрированного результата. Код `2`: ошибка
запуска или публикации. В stdout — краткий JSON-отчёт. Диагностика, источники
экспериментов и снимок лучшего результата остаются в `.agent-*` рядом с задачей.
Старый `submission.csv` сам по себе не считается результатом нового запуска.

## Что реализовано

- OpenAI-compatible `chat/completions`, прямой tool calling без MCP.
- Отдельный процесс на эксперимент, таймаут, мониторинг памяти дерева
  процессов, ограничение вывода и потоков; окружение без API-ключей.
- Ограниченные повторы 429/5xx/сетевых ошибок; ошибки авторизации завершают API-цикл.
- Резерв времени на финализацию, лимиты шагов, API-попыток и токенов.
- Проверка CSV: столбцы, строки, ID и порядок по шаблону, уникальность,
  числовые значения, допустимые метки. Ограничение файла — 256 МиБ.
- Лучший кандидат сохраняется отдельным снимком; ошибки последующих
  экспериментов и API не уничтожают его. Финальный refit может заменить
  кандидат с равной оценкой через `final: true`.
- Упаковка только runtime-файлов и разрешённых корневых ML-модулей.

Сначала LLM устанавливает контракт `configure_submission`, затем запускает
эксперименты и вызывает `register_candidate`. `finish` публикует лучший
проверенный CSV. Сравниваются только одинаковые metric/direction/validation_id.
Числа метрик задаёт ML-модуль; бэкенд не подтверждает качество модели.

## Интеграция тиммейта

См. [контракт ML](docs/ML_CONTRACT.md). Основной модуль — корневой `ml_backend.py`,
дополнительные — `ml_*.py`. Каждый вызов получает JSON-запрос, сохраняет CSV и
JSON-ответ. Пример без обучения: `examples/mock_ml_backend.py`; он исключён из
боевой упаковки. Если модуль ещё не подключён, доступен инструмент `run_python`.

## Настройки

Все числовые параметры задаются переменными окружения с префиксом `AGENT_`:

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| TOTAL_SECONDS | 10500 | Общий бюджет, максимум 10800 |
| RESERVE_SECONDS | 900 | Резерв финального обучения |
| CALL_SECONDS | 1800 | Верхняя граница Python-вызова |
| API_SECONDS | 90 | Таймаут API-запроса |
| MAX_STEPS | 60 | Число ответов LLM |
| MAX_API_ATTEMPTS | 80 | Число попыток с повторами |
| MAX_TOKENS | 200000 | Бюджет учтённых токенов на запуск |
| RESPONSE_TOKENS | 4096 | Максимум токенов ответа |
| CONTEXT_BYTES | 100000 | Ограничение истории |
| RETRIES | 2 | Повторы одного API-запроса |
| MEMORY_MB | 28000 | Порог суммарной RSS дочерних процессов |
| THREADS | 8 | Потоки BLAS/OpenMP, максимум 8 |

При отсутствии usage и сетевых сбоях токены учитываются консервативно по
байтовой оценке запроса плюс предел ответа. Это **не рублёвый лимит**:
дневной бюджет 600 ₽ общий для команды, его контролирует прокси организаторов.
Тарифы и остаток средств API нам не предоставлены. Параллельные запуски имеют
раздельные локальные бюджеты. Повторы SDK отключены, чтобы не удваивать повторы.

## Проверка и упаковка

Для разработки достаточно зависимостей бэкенда:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install openai==1.68.2 httpx==0.28.1 pydantic==2.10.6 psutil==6.1.1
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python pack_solution.py dist/solution.zip
```

На Windows используется `.venv\Scripts\python.exe`. Тесты используют маленькие
искусственные CSV и локальный HTTP-сервер, не тратят API-бюджет и не обучают ML.
ZIP включает `solution.py`, модули оркестрации, `requirements.txt` и корневые
`ml_*.py`, если они есть. Перед сборкой проверьте эти ML-модули: не храните в них
секреты и тестовые заглушки. Данные, документация, тесты, `.env` и `main.py`
в архив не попадают. Максимальный размер — 100 МБ.

## Границы проверки

Подпроцесс не является защищённой песочницей: изоляцию файлов, сети, CPU и
жёсткие квоты обеспечивает платформа. Мониторинг RSS дискретный; переменные
потоков не ограничивают произвольный Python-код. См. [безопасность](docs/SECURITY.md).
Снимки восстанавливают результат при обработанных сбоях, но возобновление после
жёсткого завершения всего процесса не реализовано. Успех бэкенд-тестов не
заменяет запуск с настоящим прокси и проверку ML-части.
