# Расширение покрытия задач

26 октября 2026. По уточнению участника предыдущая отправка получила729,491,
место189/218; последующая660,561. Скриншот, формула и детализация скрытой оценки

## Изменения

- Явно объявленная основная метрика имеет приоритет над примерами и
  вспомогательными метриками. Она также задаёт тип задачи. Конфликт требует
  явного request.metric вместо ошибочной стартовой регистрации.
- Временная валидация распознаёт строгие ISO-даты и более100 числовых
  timestamps. Будущий test проверяется на последних периодах, а не случайном
  holdout. Разрешения дат Parquet нормализуются до наносекунд.
- Для распознанных дат добавлены числовое время и календарь: месяц,
  день недели, день года и час. Явная categorical_features сохраняет исходный
  категориальный режим. Неоднозначные локальные форматы не угадываются.
- Портфель получил отдельный кандидат Ridge/LogisticRegression: train-only
  медиана, индикаторы пропусков, масштабирование и разреженный OHE.
  Деревья не продолжают линейную зависимость за пределами обучающих значений;
  линейный кандидат закрывает этот пробел без замены прежних моделей.
- Длинные разнообразные текстовые колонки внутри линейного кандидата
  получают train-only TF-IDF слов/биграмм. Словарь ограничен20k на колонку,
  число текстовых колонок — четырьмя. Это эвристика для текстовых полей
  таблицы, не универсальная поддержка изображений, аудио или документов.
- Кандидат сохраняется только при улучшении на том же разбиении. Линейный
  опыт выполняется после сохранения портфеля деревьев, до20 секунд
  планируемого обучения и с резервом30 секунд. Sklearn проверяет дедлайн
  до/после fit; жёсткое ограничение обеспечивает внешний процесс worker.
  На больших задачах при отсутствии времени этот опыт пропускается.
- Проверенные holdout-предсказания компонентов ансамбля используются
  повторно вместо второго такого же predict. Проверка исходной оценки
  каждого компонента сохранена. История и лаги совместимы с новыми признаками.

## Парные проверки

Старая сборка: SHA256
`8b56a1a92e63d430a0a38b27b773b0ac6d1a2d7b935002de4d4eb8a4f0ea4a14`.
Это сохранённый предыдущий релиз; хеш фактически загруженного участником ZIP
отдельно не сверялся. Все новые проверки используют настоящее обучение и
интерфейс python solution.py task.md; внешних API нет. В парном пилоте
настроен локальный finish-сервер. Sandbox блокировал часть обращений к
localhost: эти запуски завершились через штатное восстановление нативного
результата. Финальный тест дат и текста повторён с доступным сервером:
ровно один finish-вызов на запуск, те же метрики. Это проверка нативного
конвейера, не измерение пользы LLM.

Для каждой пары одинаковы исходные данные, внешнее разбиение,90 секунд warmup
и2 потока. Внешние ответы находятся вне worker и копируются проверяющему
только после завершения решения. Подбор модели использует внутренний holdout.

Это одна внешняя выборка, без статистического подтверждения разницы.
Публичные splits ранее использовались в пилоте; они являются контролем
регрессий, а не новым слепым тестом. Вклад LLM отдельно не измерен.

## Воспроизведение

```sh
python -m qa.compare_generalization --old old.zip --new new.zip --root .test-temp/paired --budget 90 --threads 2
python -m qa.compare_generalization --old old.zip --new new.zip --root .test-temp/public --specs specs.json --budget 90 --threads 2
python -m qa.compare_special_cases --old old.zip --new new.zip --root .test-temp/special
```

Каждый повтор требует новый root; генераторы и outer split имеют фиксированные
seeds. Источники публичных данных —в TRANSFER_DATASETS.json.
Новую официальную оценку может дать только повторная отправка на платформу.
