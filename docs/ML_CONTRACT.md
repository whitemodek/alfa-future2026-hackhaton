# Интеграция с ML-модулем

Бэкенд управляет LLM, процессами, бюджетами, журналом, проверкой CSV и публикацией.
Встроенный `ml_backend.py` обрабатывает табличную регрессию и классификацию с
одним таргетом. Контракт позволяет заменить его другим ML-исполнителем.

## Вариант 1: Python-инструмент

`run_python(code, timeout_seconds?)` выполняет код новым процессом в каталоге
`task.md`. Между вызовами остаются только файлы. Код может вызывать функции
ML-модуля; каталог решения следует добавить в `sys.path`, если он отличается
от каталога задачи. Не полагайтесь на глобальные переменные предыдущего вызова.

## Вариант 2: модуль `ml_backend.py`

Файл уже находится в корне рядом с `solution.py`. Инструмент `run_backend` запустит
его как `__main__` в ограниченном дочернем процессе с аргументами:

```text
ml_backend.py /absolute/request.json /absolute/response.json
```

Запрос:

```json
{
  "version": 1,
  "task_path": "/data/task.md",
  "task_dir": "/data",
  "time_budget_seconds": 600,
  "threads": 8,
  "memory_mb": 28000,
  "request": {"action": "experiment", "hypothesis": "..."}
}
```

Встроенные действия: `inspect` возвращает описание данных, `baseline` строит
Dummy-модель, `experiment`/`train` проверяют CatBoost против baseline на том же
holdout и пробуют полный refit. При нехватке времени или сбое refit сохраняется
обученная на части данных модель. `finalize` помечает результат финальным,
только если полный refit завершён.
`search` сначала выполняет обычный experiment. Если обучение завершилось быстро
и осталось достаточно времени, проверяет до двух соседних глубин дерева на том
же разбиении. Ошибка или худшая оценка не заменяет лучшую модель. Дорогой первый
запуск отключает дополнительные попытки. Стартовый warmup использует `search`.
`refit` с `manifest_path` дообучает уже выбранную модель без повторного поиска
на holdout. Используются сохранённые настройки и число деревьев; исходная
проверенная оценка сохраняется. Перед этим сверяются хеши данных и модели,
идентичность разбиения и воспроизводимость оценки сохранённой моделью.
Манифест должен находиться внутри `.ml-artifacts`. При неполном дообучении
финальный кандидат не выдаётся. Оркестратор делает одну такую попытку для лучшей
нативной модели перед завершением, если есть время и запуск не отменён.
Время и ресурсы верхнего уровня задаёт оркестратор. Рабочая директория
всегда `task_dir`. Пути в исходном условии нужно сопоставлять с реальными файлами.

Явные параметры: `train_path`, `test_path`, `sample_path`, `target`, `id_columns`,
`problem_type` (regression/classification), `prediction_type` (label/probability),
`metric`, `direction`, `positive_class`, `class_order`, `categorical_features`.
Настройки модели: `iterations`, `depth`, `learning_rate`, `random_seed`,
`auto_class_weights`; `refit: false` отключает полное дообучение.
Разбиение: `validation_fraction` и `split` (auto/random/time/group).
По умолчанию `auto` ищет явный переход теста в более поздние периоды среди
временных признаков и выбирает полные последние периоды для holdout. При большом
числе повторяющихся наборов признаков выбирается групповой holdout без пересечения
одинаковых строк. В остальных случаях используется random со стратификацией,
когда она возможна. Это эвристика по признакам, без доступа к ответам теста.

`time_column` задаёт временной столбец, порядок исходных строк не важен.
`split=time` без столбца использует порядок строк, который обеспечивает вызывающий.
`group_columns` задаёт признаки группы, включая ID сущности, исключённый из модели;
`group_by_features: true` группирует по всем модельным признакам.
Результат содержит `validation.strategy`, `rationale` и диагностику пересечений.
Все эксперименты должны сохранять одно разбиение: другой `validation_id` не заменит
ранее принятый результат. Если независимый holdout невозможен, автоматический
выбор оставляет score пустым. Многократный групповой CV не встроен.

CSV, TSV и Parquet читаются автоматически; шаблон ответа нормализуется в CSV
внутри `.ml-artifacts`, исходные данные не меняются. Для неоднозначных имён
файлов, таргета или порядка вероятностных столбцов требуется явный параметр.

Ответ: JSON-объект до 64 KB, UTF-8, без NaN/Infinity. Рекомендуемый формат:

```json
{
  "version": 1,
  "status": "ok",
  "candidate_path": "candidate.csv",
  "schema": {
    "columns": ["id", "target"],
    "expected_rows": 100,
    "id_columns": ["id"],
    "numeric_columns": ["target"],
    "sample_path": "sample_submission.csv"
  },
  "score": 0.75,
  "metric": "macro_f1",
  "direction": "maximize",
  "validation_id": "stratified-seed42-split-v1",
  "notes": "Description of experiment and saved model/script"
}
```

При запуске CLI оркестратор сначала автоматически вызывает baseline и search,
проверяет и регистрирует их результаты до первого обращения к API. Их бюджеты
ограничены `AGENT_BOOTSTRAP_SECONDS`/`AGENT_WARMUP_SECONDS` и оставшимся временем.
Каждый успешный `run_backend` с кандидатом также автоматически проверяет и
регистрирует CSV до следующего обращения к LLM. Итог проверки находится в поле
`registration` ответа инструмента. Для кандидатов из `run_python` нужно вызвать
`configure_submission` и `register_candidate` самостоятельно. Для резервного кандидата
можно не передавать score. Для сравнения нужны одинаковые metric, direction и
validation_id; бэкенд проверяет формат, а достоверность оценки обеспечивает ML.
Финальный refit использует ту же проверенную оценку выбранной конфигурации:
передайте `final: true` в `register_candidate`, чтобы один раз заменить кандидат
при равной оценке. Без этого флага равная оценка не заменяет сохранённый результат.

Встроенный ML-модуль возвращает `fit_scope` (`holdout_train` или `full_train`)
и `training_rows`, чтобы различать обучение на части данных и полный refit.
Оценка в обоих случаях получена на holdout до полного дообучения.
`selected_iterations` и `training_parameters` в манифесте сохраняют выбранное
число деревьев и настройки. Обучение останавливается по функции потерь, а среди
полученных деревьев выбирается лучшая целевая метрика, если CatBoost поддерживает
её эквивалент. Это позволяет использовать Macro F1 без слишком ранней остановки
на её временном плато.

После первого принятого кандидата схема фиксируется. `sample_path` задаёт
точные столбцы и число строк, а `id_columns` дополнительно проверяет порядок ID.
Для числовых предсказаний указывайте `numeric_columns`, для классификации —
`allowed_values` со списком допустимых меток по столбцам. Без sample порядок ID
проверить невозможно, поэтому используйте шаблон организаторов, когда он есть.

Сохраняйте модели и код в каталоге задачи. Каждый вызов должен завершаться до
выданного бюджета и писать ответ только после сохранения кандидата. API-ключи
не передаются дочернему процессу. Установка пакетов и сеть в ML-модуле не нужны.

`examples/mock_ml_backend.py` — тестовый исполнитель контракта без обучения.
Его нельзя класть в боевой ZIP. Упаковщик включает только корневые `ml_*.py`;
дополнительные ML-модули называйте с этим префиксом. Вложенные пакеты платформа
не переносит.
