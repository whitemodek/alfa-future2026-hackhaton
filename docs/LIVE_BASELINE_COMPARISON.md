# Проверка baseline с реальным API

Это исследовательский прогон на открытом Wine Quality White, а не оценка
организаторов и не воспроизведение скрытого теста. Архив решения не изменён.

## Протокол

- 4 898 строк, 11 числовых признаков, исходные классы качества 3–9.
- Внешнее разбиение: 3 912 обучающих и 986 проверочных строк. Совпадающие
  векторы признаков остаются в одной группе; seed 20261031.
- Внешние ответы доступны только проверяющему коду после обучения.
- Использованы исходные prompt и исполнитель baseline организаторов;
  MCP заменён прямыми вызовами. Добавлены переменные окружения Windows,
  лимиты CPU и времени. Это адаптация, а не неизменённый baseline.
- Максимум шесть вызовов API на сторону и 15 000 токенов на сторону,
  включая продолжения и диагностику. Исходный baseline допускает 100 шагов.
- Нативная сторона использует код из `solution-agent-fix.zip`.

## Наблюдения

Первый прогон baseline остановился без CSV: три вызова ушли на изучение данных,
следующий запрос не прошёл предварительное резервирование бюджета. Нативная
сторона сохранила корректный CSV с Macro F1 **0,265770**. Это подтверждает
наличие рабочего резервного результата, но не превосходство над завершённым
baseline: завершённого результата baseline здесь нет.

Укороченный prompt не улучшил внешний F1. Проверка API показала, что
`reasoning.effort=none` принимается используемым прокси и в диагностике даёт
ноль reasoning-токенов. Текстовая команда `/no_think` такого эффекта не дала.
Экономия reasoning сама по себе не подтверждает улучшения качества модели.

В последующем прогоне с общим профилем baseline предложил Random Forest,
но за оставшиеся вызовы выполнил только CV и не сохранил CSV. Его случайный
стратифицированный CV не защищал от повторяющихся векторов признаков;
полученные там оценки нельзя сравнивать с нашим групповым holdout.

В экспериментальном адаптере нативной стороны ограничение списка инструментов
также заблокировало внутреннюю регистрацию кандидата (`ValueError`). Поэтому
этот этап нельзя использовать как проверку качества изменённого оркестратора.
Сохранённый исходный CSV остался доступен. Производственный код инструментов
не менялся; ошибка относится к исследовательскому адаптеру.

## Отдельное воспроизведение предложенной модели

Без дополнительных API-вызовов обучен именно предложенный RF:
`RandomForestClassifier(n_estimators=300, random_state=42, n_jobs=2)`.
Настройки зафиксированы до чтения внешних ответов.

| Модель | Внутренний групповой Macro F1 | Внешний групповой Macro F1 |
|---|---:|---:|
| Сохранённый нативный кандидат | 0,295823 | 0,265770 |
| RF300, отдельное воспроизведение | 0,263809 | 0,284479 |

RF выиграл на внешней части, хотя проиграл на внутренней. Это иллюстрирует
неустойчивость выбора по одному разбиению. Внешний результат уже просмотрен;
его нельзя дальше использовать как независимый контроль для настройки.
Это не официальный B_F1 и не завершённый результат агента baseline.
