Работа ведётся в `codex/confirmed-selection`. Основная ветка и ранее
собранные ZIP не заменены. Новых отправок на платформу и платных вызовов API
нет. Машиночитаемая сводка — `FOLLOWUP_RESULTS.json`; локальные модели и
данные остаются в `.test-temp/` и в репозиторий не публикуются.

В дополнительном полном forward-прогоне модели выбирались только на прошлом,
затем дообучались на всех доступных прошлых строках и предсказывали целиком
следующий период. Для периода5 контроль дал **42,722079**, остаточная смесь —
**42,859512**: улучшение кэша не перенеслось в этот режим. На периоде4 исходный
контроль оказался `history`, а не `lag`, и первоначальный исследовательский
запуск остановился как неподдерживаемый. После этого скрипт получил явное
сохранение контроля для таких случаев; старый частичный отчёт не объявляется
завершённым или успешным.

## Диагностика распределений

Только по признакам обучена модель принадлежности строки к train/test,
с групповыми OOF-предсказаниями. AUC — **0,816480**. Это свидетельство
различимости распределений, а не метрика решения задачи и не доказательство
причины платформенного балла. Ответы test не использовались.

Поправка на доли классов мотивирована
[исследованием label shift, ICML 2020](https://proceedings.mlr.press/v119/alexandari20a.html).
Предположение стабильности условных распределений классов и калибровка здесь
не подтверждены; результат эксперимента отрицательный.

## Более дорогие эксперименты

В окружение проекта установлены предусмотренные платформой AutoGluon 1.3.1
и Torch 2.5.1. Для установки использованы ограничения версий из исходного
`requirements.txt`; сам файл зависимостей не изменён.

В AutoGluon каждому одинаковому вектору признаков назначается один из трёх
номеров фолда. В параметр `groups` передаются эти номера, а не десятки тысяч
уникальных сущностей. Это соответствует механизму LeaveOneGroupOut из
[API AutoGluon 1.3.1](https://auto.gluon.ai/1.3.1/api/autogluon.tabular.TabularPredictor.html).
Маркер фолда исключён из признаков. Собственные классы моделей рассчитывают
SqrtBalanced внутри каждого обучающего фолда, включая веса CrossEntropyLoss
нейросети. Внутренний скор стекинга не считается независимой оценкой:
внешняя групповая часть не передаётся в обучение и отбор.

Первый AG-прогон остановлен **до внешней оценки**: медленный CatBoost
монополизировал бюджет L1. Новый протокол задаёт лимиты по моделям и порядок,
позволяющий обучить разные семейства. Старый незавершённый прогон сохранён.

Отдельно проверена собственная CPU-реализация MLP с разделяемыми весами и
ранговыми множителями ансамбля, мотивированная
[TabM, ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/c1ba41c694834aeef91ae161711d4939-Abstract-Conference.html).
Это **не официальная реализация TabM и не воспроизведение его результатов**.
Численные интервалы и категории обучаются только на train-фолде; число эпох
и вес в смеси выбираются только внутри development-части. Готовые веса
не скачиваются. Она дала ΔMacro F1 +0,005459 и −0,004474, порог не пройден.
AutoGluon также завершил оба внешних прогона, но не прошёл общий порог;
точные показатели сохранены в `FOLLOWUP_RESULTS.json`. Ни один из этих
вариантов не заменил финальный архив.

После сообщения участника об окончании соревнования активные исследования
прекращены. На момент проверки незавершённых процессов обучения не было.
Код и отрицательные результаты сохранены в экспериментальной ветке.

## Новые интерфейсы и проверки

Экспериментальные запросы: `validation_seed`, `duplicate_weighting`,
`flow_features`, `action=seed_bag`, `action=residual`. Они не включены
в стандартный стартовый портфель. Неудача не меняет существующий кандидат.
Проверены сохранение групп, отсутствие проверочных строк в обучении,
неизменность ответов без истории, контроль конфигураций, загрузка и точный
полный refit с сохранением исходной оценки.
