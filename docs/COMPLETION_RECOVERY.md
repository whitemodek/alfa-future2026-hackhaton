# Исправление преждевременного завершения агента

26 октября 2026. Участник уточнил баллы: предыдущая отправка729,491,
следующая660,561. Снижение68,930, примерно9,45%. Ранее записанное7,2949
было неверным масштабом. Формула оценки и журналы платформы недоступны.

## Подтверждённый дефект

При наличии стартового кандидата любой ответ LLM без tool calls немедленно
завершал run с reason=completed. Даже фраза о намерении обучить модель
останавливала выполнение до следующего вызова инструмента.

Дефект воспроизведён тестом до исправления: стартовый кандидат0,5 сохранялся,
а следующий корректный вызов с кандидатом0,9 не выполнялся. Tool calls были
валидны, лимиты не исчерпаны. Этот код совпадал в двух отправках, поэтому
дефект нельзя объявлять установленной причиной снижения балла.

Теперь агент напоминает о протоколе и допускает до двух повторных текстовых
ответов подряд. Явный finish завершает работу сразу. При исчерпании повторов
сохраняется лучший кандидат с reason=invalid_completion; ограничения времени,
API-вызовов и токенов продолжают действовать. Выбор моделей и валидация
не изменены. Успешный вызов инструмента сбрасывает счётчик текстовых ответов.

`dist/solution-agent-fix.zip`:61560 байт, SHA256
`e1be329dea094274ecaf18895a8166bcff78480524a1e3a310ae44cb6cab82ef`.

База — предыдущий локальный релиз SHA256
`8b56a1a92e63d430a0a38b27b773b0ac6d1a2d7b935002de4d4eb8a4f0ea4a14`.
По истории это релиз до изменений последующей отправки; хеш действительно
загруженного участником файла отдельно не сверялся.
Сравнение содержимого ZIP подтверждает: изменён только agent.py,
остальные12 корневых файлов совпадают побайтово. Новые линейные модели,
TF-IDF, календарные изменения и исследовательские стратегии не добавлялись
к этой базе. Это отдельный кандидат для измерения изменения оркестрации.

Исходники main содержат последующие ML-расширения; обычная сборка main
поэтому отличается от этого контролируемого архива. Для него предназначена
отдельная ветка codex/submission-agent-fix, содержащая только13 runtime-файлов.
Обычный dist/solution.zip и codex/submission остаются предыдущей сборкой.

## Проверки

- Полный набор после исправления:325 тестов на Windows,324 успешных,
  один пропуск из-за прав ОС на символьную ссылку.
- Отдельно проверены последующее улучшение после текста, ограниченные
  повторы, сохранение кандидата и отсутствие дополнительных запросов после finish.
- Парный запуск через локальный HTTP-провайдер и настоящий LightGBM:
  старый агент сделал1 запрос и оставил baseline с внешним RMSE5,849834;
  новый сделал3 запроса и дошёл до обучения, внешний RMSE0,544423.
- Внешние ответы копировались проверяющему после выхода worker, исходные
  файлы неизменны, платного API нет.

Провайдер в парном тесте исполняет фиксированный сценарий. Это доказательство
исправления конкретного сбоя, а не оценка качества настоящего LLM или
прогноз роста leaderboard. Если LLM и раньше явно вызывал finish, данная
правка не заставит его выполнять дополнительные опыты и может не изменить балл.

Команда воспроизведения с новым каталогом:

```sh
python -m qa.check_completion_recovery --base prior.zip --output dist/solution-agent-fix.zip --root .test-temp/completion-fresh
```

## Дополнительная проверка обучаемого ансамбля

Проверен один заранее заданный LogisticRegression stacker на логарифмах
сохранённых out-of-sample вероятностей трёх моделей. Результат хуже на обоих
групповых разбиениях; в runtime он не включён.
При аудите установлено, что исторический early stopping базовых моделей
использовал будущую meta-validation часть. Внешние ответы не использовались
для fit, но meta-validation нельзя считать независимой для всего конвейера.
Это дополнительная причина не переносить эксперимент в рабочее решение.
Macro F1 изменился0,654210→0,616211 и0,660766→0,625432.
Все четыре логистические модели достигли лимита500 итераций без сходимости;
это результат конкретного бюджетного варианта, не вывод о любых stacking-моделях.
Шесть специальных тестов прошли; исходники и артефакты сохранены отдельно.
