# Что следует из переданной формулы

Пользователь передал разбор DeepSeek с формулой, предположительно из регламента.
Исходный baseline.py позднее найден по ссылке из предыдущего чата и прочитан:
см. ORGANIZER_SOURCES.md. В нём нет формулы или значений B_RMSE/B_F1.
Сам PDF пока не найден. Поэтому ниже — условный математический разбор,
не подтверждение правил платформы.

При положительном B_RMSE и 0<=B_F1<1:

```
S_reg = 100 * max(0, 1 - RMSE / B_RMSE)
S_cls = 100 * max(0, (F1 - B_F1) / (1 - B_F1))
Score = (S_reg + S_cls) / 2
```

1. При корректных RMSE>=0 и F1 в[0,1] итог лежит в[0,100]. Сообщённые
   значения729,491 и660,561 не могут быть прямым результатом этой формулы.
   Возможное преобразование отображения нужно подтвердить исходным регламентом;
   автоматически делить числа на100 нельзя.
2. Score7,29 означает только сумму вкладов14,58. Например, S_reg8 и S_cls6,58
   дают тот же балл, хотя обе задачи выше baseline. Нулевой вклад одной задачи
   из общего балла установить нельзя; утверждение о его вероятности требует
   дополнительных данных.
3. При S_cls0 потолок равен50. Поэтому результат29,68 математически можно
   превысить одной регрессией: для этого нужен S_reg>59,36.
4. Локальные37,17 и0,656 относятся к нашим holdout, не к скрытому тесту.
   Их нельзя без оговорок подставлять вместо скрытых метрик платформы.
5. Локальный запуск предоставленного baseline полезен только в паре с нашим
   решением на одинаковых данных, разбиении, метрике и ресурсах. Он не раскрывает
   официальные B_RMSE/B_F1 скрытого теста. LLM-бейзлайн также может быть
   недетерминированным и зависеть от модели/версии/бюджета.

Самый полезный следующий источник информации — сам регламент и baseline.py:
какие именно задачи, данные и метрики входят в оценку; где зафиксированы B;
как нормированный балл отображается на странице. Последнюю отправку не следует
тратить на загрузку baseline ради попытки восстановить два неизвестных порога
из одного суммарного числа.
