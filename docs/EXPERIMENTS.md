# Проверка качества моделей

25 октября 2026. Использованы только train, признаки test и условия организаторов.
Ответы скрытого теста недоступны. Все значения ниже относятся к holdout.

## Разбиение

В регрессии train содержит периоды 1–5, а test — только период 6.
Проверка теперь использует целиком период 5: 35 000 строк обучения и
18 308 строк валидации. Порядок строк исходного CSV не влияет на выбор.

В классификации 43,94% строк прежней случайной валидации имели точный
дубликат признаков в обучающей части. В настоящем test таких строк только
8,64% относительно полного train. Теперь одинаковые наборы признаков остаются
в одной группе: 70 136 строк обучения и 17 534 строки валидации, без пересечений.
Все десять классов присутствуют в обеих частях. ID исключён из признаков.

Новые оценки нельзя напрямую сравнивать с прежним случайным holdout.
Группировка устраняет точные дубликаты, но не доказывает отсутствие всех
скрытых связей между наблюдениями или совпадение распределений train/test.

## Сравнение настроек

Регрессия: одинаковый holdout периода 5, seed 42, learning_rate 0,06,
до 800 деревьев, early stopping 60, четыре потока.

| Глубина | Выбранных деревьев | RMSE |
|---|---:|---:|
| 4 | 129 | 46,8863 |
| 6 | 70 | 47,5278 |
| 8 | 69 | 45,6871 |

Глубина 8 перспективна для этой задачи. Общая настройка для всех задач
не менялась по результату одного набора данных; агент может сравнивать глубины.
Финальный встроенный `search` сам повторил эти сравнения за 18,39 секунды,
выбрал глубину 8 и дообучил 69 деревьев на всех 53 308 строках. Поиск запускает
соседние конфигурации только при быстром первом обучении, максимум три попытки.
Отчёт: `.test-temp/search-regression-proof.json`.

В классификации прямая ранняя остановка по Macro F1 оказалась хуже:
0,59541 против 0,61539 у контрольного запуска по loss на том же разбиении.
Этот вариант отклонён: F1 может долго стоять на плато до улучшения редких классов.

Принятый вариант использует loss для остановки и выбирает число деревьев по
целевой метрике среди уже обученных. На одной общей траектории из 217 деревьев:

| Выбор контрольной точки | Деревьев | Macro F1 |
|---|---:|---:|
| По loss | 217 | 0,602170 |
| По Macro F1 | 212 | 0,603125 |

Прирост небольшой: 0,000956. Это сравнение одной траектории, не разных
запусков с разным временем обучения. Проверенная метрика записывается до refit;
полная модель не получает новую оценку на уже использованных для обучения строках.

Локальные исходные отчёты: `.test-temp/ml-robust-experiments.json` и
`.test-temp/primary-selection-verification.json`. Они и данные не входят в ZIP.

## Дополнительный этап: три семейства и повторная проверка

Глубина 6 XGBoost отклонена как общий дефолт: улучшение первого периода не

Вторичный выигрыш ансамбля небольшой; его доверительный интервал пересекает ноль.

исправил этот случай и воспроизвёл результат 44,6235 в настоящем runtime-адаптере.
Словари категорий обучаются на train-fold; числовые нули остаются нулями.
Поиск ограничивает расширение плотной матрицы до 50 млн ячеек.

Исходные отчёты: `.test-temp/night-regression-summary.json`,
`.test-temp/night-regression/adapter-report.json`, `fixed-seed-bags.json`.

## Повторная проверка дополнительных улучшений

Две стратегии новых признаков проверены по прежнему вложенному групповому
протоколу: список/статистика выбираются только на внутреннем train, затем
фиксируются для внешнего refit. Внешние ответы не используются для обучения.
В таблице приведены Macro F1 на основном и подтверждающем разбиениях.

| Изменение | Модель | Основной: было → стало | Подтверждающий: было → стало |
|---|---|---:|---:|
| Частоты категорий | LightGBM63 | 0,64148 → 0,64835 | 0,66294 → 0,66026 |
| Частоты категорий | XGBoost6 | 0,65191 → 0,64001 | 0,64997 → 0,64652 |
| Целочисленные признаки с 2–16 значениями как категории | LightGBM63 | 0,64148 → 0,63730 | 0,66294 → 0,65331 |
| То же | XGBoost6 | 0,65191 → 0,64441 | 0,64997 → 0,65169 |

Устойчивого выигрыша нет, обе автоматические стратегии отклонены. Для опыта с
ролями исправлены экспериментальные вызовы LightGBM: предварительные прогоны,
где новая роль не доходила до fit, исключены; таблица содержит только корректные
повторные опыты. Промежуточное улучшение одного разбиения не стало основанием
для изменения дефолтов.

Сравнение вычислительного бюджета выполнено при одинаковых четырёх потоках.
Warmup 300/600 секунд дал один F1 0,655436; фактическое время выросло с 172,9
до 244,2 секунды. Регрессия с увеличенным бюджетом осталась на RMSE 43,272422.
XGBoost patience 180 также сохранил 300 выбранных деревьев и F1 0,644415.
Дефолтные warmup и patience сохранены.

Дополнительно те же выбранные параметры и числа деревьев без нового early stopping
проверены на grouped17: ансамбль обоих расписаний дал F1 0,651824. Разбиения
пересекаются по исходным данным; это проверка чувствительности CV, не внешний тест.

В код вошли два исправления: отдельная предобработка каждой модели внутри ансамбля
и выделение бюджета refit только компонентам, которые ещё не обучены на полном train.
Оба подтверждены тестами с настоящими моделями и сохранёнными артефактами.

Отчёты: `.test-temp/feature-frequency-report.json`,
`.test-temp/feature-role-report.json`, `.test-temp/schedule-summary.json`.
Новых платных API-вызовов нет.

## История сущности и причинные лаги

Проверена гипотеза повторных наблюдений зданий. Структурный ключ включает
регион, класс, назначение, площадь и год постройки; он не подтверждён как
постоянный building ID. Из истории исключены неполные/нечисловые бесконечные
ключи и все ключи с несколькими наблюдениями внутри обучающего периода.
Используется только последнее строго прошлое значение таргета.

Первый кандидат — фиксированные 50% прежнего ансамбля и 50% истории для
совпавших ключей, прежний ансамбль для остальных. Второй — фиксированные
50% первого кандидата и 50% XGBoost с двумя дополнительными признаками:
строго прошлый таргет и индикатор наличия. Лаги обучающих строк строятся
до добавления ответов их периода; внешние ответы отсутствуют во входных
данных построителя. Нет заполнения глобальным средним таргетом.

| Контрольный период | Прежний ансамбль RMSE | История | История + XGB с лагами |
|---|---:|---:|---:|
| 5 | 43,272422 | 37,883175 | **37,358725** |
| 4 | 43,494349 | 33,035012 | **32,643254** |
| 3 | 55,908729 | 50,839600 | Не проверялось |

Все контрольные модели завершили обучение. Число деревьев выбиралось early
stopping на соответствующем внешнем периоде, как в предыдущих контролях:
это временной backtest, а не независимый скрытый тест. Период 3 использован
как дополнительная проверка исторической поправки; лаг-модель там не оценена.

Покрытие ключом на периодах 3/4/5 после защит — 62,72% / 74,17% / 66,42%.
По полному train покрытие test периода 6 — 76,72%; ответы test недоступны.
Добавление ELEVATION резко снижало покрытие и автоматически не применяется.
Подбор веса по предыдущему периоду не превзошёл фиксированные 0,5 устойчиво.
Huber50 и train-only winsorization 99,5% также не улучшили оба периода.

Лаг-XGBoost: depth4, lr0,04, min_child_weight5, lambda10, subsample0,85,
colsample0,9, seed42, максимум 1800 деревьев, patience100. Выбраны 265/305
деревьев. Рабочий модуль с настоящими манифестами воспроизвёл обе оценки
точно; полный refit сохранил исходный float и отдельную holdout-модель.

Разница RMSE лаг-кандидата с простой историей при парном bootstrap:
период5 [-0,7765; -0,2778], период4 [-0,7729; +0,0034]. На подтверждающем
периоде интервал немного пересекает ноль; статистическая гарантия не заявляется.
Доверительный интервал не учитывает всю неопределённость выбора конфигураций.

В автоматическом портфеле глубина CatBoost регрессии 8 запускается первой,
чтобы этот подтверждённый контроль не зависел от того, разрешит ли загрузка
CPU соседний поиск. Явная глубина пользователя сохраняет приоритет.

Отчёты: `.test-temp/late-regression-entity-report.json`,
`.test-temp/late-regression-report.json`, `.test-temp/late-lag-feature-report.json`,
`.test-temp/lag-runtime-proof.json`. Все опыты локальные, платных вызовов нет.

## Дополнительный ExtraTrees для классификации

Протокол прежний вложенный: два внешних групповых разбиения; параметры
предобработки и выбор min_samples_leaf из 1/3 — только во внутреннем train.
На обоих разбиениях выбрано 3. SqrtBalanced рассчитывается по train-fold.
Числовые пропуски заполняются медианой с индикатором, категории — train-only
One-Hot с игнорированием неизвестных. max_features=1, seed42.

| Фиксированный ансамбль | Основной Macro F1 | Подтверждающий |
|---|---:|---:|
| LightGBM63 + XGB6, 50/50 | 0,649651 | 0,655315 |
| LightGBM63 + ExtraTrees300, 50/50 | 0,653237 | 0,663357 |
| Три модели, поровну, ExtraTrees300 | 0,654223 | 0,657309 |
| LightGBM63 + ExtraTrees100, 50/50 | 0,654919 | 0,661615 |
| Три модели, поровну, ExtraTrees100 | 0,654210 | 0,660766 |

ExtraTrees100 обучался 19–24 секунды, артефакт около 150 МБ; 300 деревьев
не дали доминирования на обоих разбиениях. По парному групповому bootstrap
интервалы улучшения ExtraTrees300-пары пересекают ноль. Лес добавлен как
проверяемый кандидат, универсальное превосходство не утверждается.

Первоначальные сравнения сохранённого исследовательского леса с native-моделями
нельзя приписывать нативному адаптеру. Дополнительная сверка выявила различие
округления двух математически эквивалентных формул SqrtBalanced после нормировки:
1,8–3,6 × 10^-15. Это меняет выбор разбиений ExtraTrees. Эффективные признаки
после float32 совпадают точно; one-shot и warm-start с одинаковыми весами дают
одинаковые деревья и классы. Замена только весов при том же X воспроизвела
предсказания соответствующего исследовательского/нативного леса.

Проверен именно рабочий адаптер с фиксированными 100 деревьями, leaf3 и весами
из ml_models.py, без нового подбора:

| Проверка | Основной Macro F1 | Подтверждающий |
|---|---:|---:|
| Native ExtraTrees100 | 0,641706 | 0,653731 |
| Cached nested LightGBM63 + XGB6 | 0,649651 | 0,655315 |
| LightGBM63 + native ExtraTrees100 | 0,651988 | 0,663569 |
| Тройной, с native ExtraTrees100 | **0,654603** | **0,657263** |

Улучшение тройного ансамбля относительно nested-пары сохраняется на обоих
разбиениях. Эти числа не смешиваются с основным runtime: там boosting-модели
выбирали число деревьев на основном holdout, а в nested-опыте — на внутреннем.
В финальном ZIP-прогоне пара дала 0,655436, тройной — **0,6562101454491613**;
выбран тройной. Полный refit сохранил исходную оценку. Прирост 0,000774 мал,
статистически значимое превосходство на скрытом тесте не утверждается.

Штраф частоты дубликатов ухудшил оба семейства на обоих разбиениях.
Train-only QuantileTransformer для ExtraTrees300 помог паре на двух split,
но был дорогим; вариант со 100 деревьями не улучшил ни один фиксированный
ансамбль на обоих split. Его pair/triple с текущими native-моделями также
не превзошли runtime. Квантильное преобразование не включено.

## Сквозной контроль времени и восстановления

Первый ZIP с лесом300 прошёл формат, но портфель исчерпал 300 секунд до
возврата результата, оставив только dummy Macro F1 0,04855. Такой запуск
отклонён как регрессия качества; успешный exit/CSV сам по себе недостаточен.

Исправлено расписание: прежний ансамбль сохраняется до optional-леса,
лес получает до 45 секунд с резервом 60, дополнительные ансамбли учитывают
измеренную стоимость предыдущих. Законченные улучшения атомарно сохраняются
до следующего опыта. При таймауте или падении следующего опыта checkpoint
восстанавливается с обычной валидацией CSV и реальным статусом процесса в логе.

Короткий тест с настоящим ограниченным процессом воспроизвёл потерю результата
за 0,53 секунды и после исправления прошёл. Проверены также worker crash,
испорченный CSV, перерасход леса, KeyboardInterrupt и дорогие ансамбли.
Повторный ZIP-прогон сохранил прежний Macro F1 и полный refit. Финальный
архив дополнительно требует финальный кандидат и отсутствие потери качества.


## Последний контроль CatBoost с лагами

После фиксации текущего конвейера проверена одна дополнительная гипотеза:
CatBoost depth8 с теми же причинными лагами и заранее заданная смесь 50/50

неизменность train/validation-признаков. Обе модели завершились без таймаута.

| Период | Текущий RMSE | CatBoost с лагами | Смесь 50/50 |
|---|---:|---:|---:|
| 5 | **37,358725** | 39,83856 | 38,21408 |
| 4 | 32,643254 | 33,46914 | **32,30441** |
