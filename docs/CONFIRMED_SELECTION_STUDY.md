# Проверка идей после сравнения с другим решением

Ветка `codex/confirmed-selection`. Нулевой расход API, ноль отправок на платформу.
Стабильные архивы сохранены. Режимы ниже не включены в стартовый портфель.

## Что реализовано

### Раздельный выбор и подтверждение

В `ml_confirmed.py` добавлен опциональный `action=confirmed`:

1. Исходный holdout резервируется для подтверждения до выбора моделей.
2. Остаток данных делится на обучение и внутренний выбор с сохранением
   групп или порядка времени. Все три части не пересекаются по строкам;
   групповой режим также сохраняет непересечение групп.
3. Фиксированный набор LightGBM, XGBoost и линейной модели оценивается
   только внутри development-части. Число деревьев выбирается там же.
4. Фиксированный контроль LightGBM и один выбранный кандидат заново
   обучаются на development целиком. Предсказания обоих сохраняются в памяти
   до первого чтения ответов части подтверждения.
5. Для замены контроля нужен выигрыш на обеих частях: не менее 0,002
   Macro F1 либо 0,5% для RMSE/MAE. Это инженерные пороги, а не доказательство
   статистической значимости. Сетки подбора на подтверждении нет.
6. Сначала сохраняется проверенная модель, затем выполняется полный refit
   с теми же параметрами и числом деревьев. Используется существующий контракт
   манифестов, контроль хешей и механизм восстановления после таймаута.

Поддержаны `macro_f1`, `rmse`, `mae`. Если независимых примеров недостаточно
для всех классов в каждой части, режим отказывается от эксперимента.
Ранее сохранённый результат остаётся у агента.

Пример запроса `run_backend`:

```json
{"request": {"action": "confirmed"}, "timeout_seconds": 180}
```

Этот режим выбирает из другого, более узкого пула, чем обычный портфель.
Изолированный контроль подтверждения — LightGBM, а не весь прежний портфель.
Поэтому подтверждённый выигрыш над этим контролем ещё не означает выигрыш
над нашим готовым решением. Внешний сравнительный прогон проверяет именно это.

### Смесь линейной модели и дерева

Опциональный запрос `{"action":"portfolio","linear_blend":true}` добавляет
одного кандидата для регрессии: 75% лучшей отдельной модели из бустингов и
25% линейной модели. Проверяются существующие holdout-модели, финальный
refit использует выбранные компоненты. Сетки весов нет. Неуспех не меняет
сохранённого победителя. По умолчанию флаг выключен.

### Настройка решений классов

В `qa/decision_weights.py` реализован исследовательский подбор ограниченных
множителей вероятностей для Macro F1. Это оптимизация решения, а не
калибровка вероятностей. Он не входит в пакет runtime.

## Полученные результаты

### Множители классов: два прежних групповых разбиения организаторской задачи

| Разбиение | Исходный F1 | С множителями | Изменение |
|---|---:|---:|---:|
| primary | 0,654210 | 0,653926 | −0,000284 |
| confirmation17 | 0,660766 | 0,660993 | +0,000227 |

Множители подобраны только по внутренним ответам, до внешней оценки.
Использованы прежние кэши ансамбля LGB/XGB/ExtraTrees; они не равнозначны
повторному прогону полного актуального решения. Внутренняя ранняя остановка
базовых моделей уже использовала внутренние ответы. Разбиения неоднократно
просматривались раньше: оценка исследовательская. Порог +0,002 на обоих
разбиениях не пройден; в runtime множители не включены.

### Раздельный выбор: пять открытых задач

Свежий фиксированный seed 20261102. На каждый кейс: 90 секунд обычному
портфелю, 90 секунд дополнительному режиму, до 30 секунд на отдельный refit;
два потока. Это дополнительный вычислительный бюджет, не сравнение равных
по стоимости алгоритмов. Источники и точные разбиения зафиксированы до запусков.

| Задача | Метрика | Обычный портфель | Новый режим отдельно |
|---|---|---:|---:|
| Energy Efficiency | RMSE ↓ | 0,300770 | 0,363564 |
| Red Wine | RMSE ↓ | 0,681360 | 0,683034 |
| Diabetes | RMSE ↓ | 61,959697 | 56,301006 |
| White Wine | Macro F1 ↑ | 0,288733 | 0,273409 |
| Digits | Macro F1 ↑ | 0,980462 | 0,983399 |

Отдельный режим лучше на двух задачах, хуже на трёх. При добавлении к обычному
портфелю выбор по исходному holdout во всех пяти случаях сохранил прежний
портфель: итоговые внешние показатели не изменились. Предварительный порог
двух заметных улучшений готового решения не пройден.

Это также показывает ограничение добавления новых кандидатов: хороший
внешний результат отдельной модели не помогает, если внутренняя процедура
выбора предпочитает другую. Выбирать по уже просмотренной внешней части нельзя.

### Линейная смесь: три открытые регрессии

Другой фиксированный seed 20261103. Контроль и смесь используют одни и те же
подготовленные модели. Выбор зафиксирован до открытия внешних ответов.

| Задача | Контроль RMSE | Итог RMSE | Решение внутренней проверки |
|---|---:|---:|---|
| Energy Efficiency | 0,417451 | 0,417451 | Сохранён контроль |
| Red Wine | 0,642109 | 0,648202 | Смесь принята, внешнее ухудшение 0,95% |
| Diabetes | 56,627496 | 56,627496 | Сохранён контроль |

Порог двух улучшений не пройден. Флаг оставлен выключенным.

## Проверки и воспроизведение

Добавлены проверки непересечения групп и времени, отсутствия проверочных
строк в обучении/ранней остановке, сохранения классов, воспроизводимости
holdout-оценки после загрузки и точного refit. Для смеси проверены фиксированные
веса и сохранение обычного контракта CSV.

Отдельные 13 проверок нового кода прошли, включая запуск `confirmed` из
распакованного плоского ZIP и проверку, что изменение ответов подтверждения
не меняет внутренние оценки или выбранное число деревьев.

```sh
python -m unittest tests.test_confirmed_selection -v
python -m qa.research_decision_weights
python -m qa.benchmark_confirmed
python -m qa.benchmark_linear_blend
```

Исследования требуют локальных данных и для первого опыта — прежних кэшей.
Существующие результаты не перезаписываются. JSON-отчёты опубликованы рядом
с этим документом; локальные входы и модели остаются в `.test-temp/`.
Полный набор на момент проверки содержал 353 теста: 346 прошли, один
пропущен, шесть не смогли обратиться к локальному HTTP-серверу в sandbox.
Повторный запуск затронутых HTTP/CLI-групп вне этого ограничения:
все восемь проверок прошли; внешнее API не использовалось.
Открытые наборы ранее исследовались, поэтому новые seeds не превращают этот
пилот в слепую проверку. Рост официального балла не подтверждён.

Решение по выпуску: сохранить новые возможности в экспериментальной ветке,
не заменять финальный ZIP и не расходовать последнюю попытку на эти варианты.
