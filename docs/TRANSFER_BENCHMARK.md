## Протокол

Внешние ответы отделены до обучения; модель получает только train/test/шаблон/условие.
Выбор моделей и числа деревьев выполняется на внутреннем разбиении train.
Внешние ответы копируются в проверяющий каталог только после выхода процесса.
Фиксированы seed 20261025 и целевая доля outer около 20%. Одинаковые наборы
признаков целиком остаются с одной стороны. Для классификации сохранены все
классы в train и outer; среди допустимых групповых folds выбран ближайший к 20%
по числу строк, без просмотра предсказаний. Для KDD получилось 4054/20000 строк.

Warmup — до 180 секунд, два потока, refit — до 300 секунд. Это сокращённый
пилот исполнения и переносимости. Основная сборка использует warmup300 и до8CPU.
Исходники, входные копии, ответы и split-метаданные сверяются по SHA-256.

## Что подтверждено и что остаётся ограничением

Конвейер исполнил новые задачи с разными схемами, размерами, целями и метриками.
Каждая модель обучалась на своём новом train. Это не дообучение LLM и не
перенос готовых весов между несвязанными таблицами. Данные организаторов
оставались отдельными; runtime не получил дополнительных исходных данных.

На Wine Quality White Macro F1 всего 0,291874: редкие классы остаются слабым
местом. Класс quality=9 содержит лишь пять исходных наблюдений. Хорошие результаты
Digits или бинарного KDD не означают такой же результат на сложной многоклассовой
задаче организаторов. Малые наборы и одно внешнее разбиение дают неопределённость.

Bank проверяется как статическая табличная классификация; клиентского ID нет,
поэтому случайный групповой split не доказывает перенос на новых клиентов или
будущие годы. Диагностический набор используется только как учебный ML-бенчмарк.
Сильные специализированные AutoML-системы при одинаковом бюджете не сравнивались.
Пилот не является оценкой скрытого теста Boosters и не определяет место команды.

## Воспроизведение

Подготовьте CSV по указанным источникам и JSON specs со свойствами name, path,
target, problem_type, metric, source_url. Существующие разбиения заморожены;
новая конфигурация требует нового root. Поддержаны RMSE, Macro F1 и бинарный ROC AUC.

```sh
python -m qa.transfer_benchmark specs.json --root .test-temp/transfer-run --prepare-only
python -m qa.transfer_benchmark specs.json --root .test-temp/transfer-run --budget 180 --threads 2
```

Параллельные процессы должны обрабатывать разные имена задач. Повторная
оценка уже завершённой задачи в том же root отклоняется. Итоговые JSON лежат
в results; источники/splits/ответы доступны для локального аудита отдельно от
каталогов worker. Ответы после результата не используются для изменения runtime.
