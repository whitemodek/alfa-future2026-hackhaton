# Проверка перед сдачей

Актуализация: 24 октября 2026. Этот файл описывает проверки и ограничения; старые замечания из предыдущего QA заменены итогами повторного прогона.

## Что проверяет QA

- `tests/test_qa_harness.py`: запуск собранного текущего ZIP с локальным HTTP-сервером вместо LLM, проверка результата независимым скриптом; повторный запуск со старым `submission.csv`; остановка зависшего процесса вместе с дочерним; большой stderr; небезопасные имена в ZIP; неверные строки, порядок ID и inf; сверка метрики с ответами.
- `tests/test_qa_e2e.py`: регрессия и многоклассовая задача с настоящим обучением sklearn. LLM заменена сценарием, метрики считаются на синтетических данных.
- Остальные тесты проверяют цикл агента, ошибки API, бюджет, процессы, выбор кандидатов и формат CSV.

Результат синтетической задачи подтверждает работу цепочки, но не гарантирует качество на скрытых данных организаторов. Реальный API проверяется отдельно коротким запуском; ключи и `.env` в архив не входят.

## Локальный прогон

```sh
python -m unittest discover -s tests -v
python qa/gen_tasks.py qa_tasks --small
python pack_solution.py dist/solution.zip
python qa/run_local.py dist/solution.zip qa_tasks --limit-min 20
```

Последняя команда использует настоящий API из переменных окружения. Ограничьте `AGENT_TOTAL_SECONDS` и `AGENT_RESERVE_SECONDS` соответственно выбранному лимиту, а также расход токенов. Параметр `--limit-min` задаёт внешний жёсткий таймаут.

`run_local.py` распаковывает архив в новую папку, копирует только данные задачи, убирает старый итоговый CSV и запускает `python solution.py /path/to/task.md`. Путь временной папки остаётся в отчёте для разбора ошибок. На Linux останавливается группа процессов; на Windows используется `taskkill /T /F` и наблюдение потомков через psutil. На Windows обнаружение очень быстро отделившихся потомков остаётся best effort.

`qa/check_submission.py` проверяет строки, колонки, ID, пропуски и конечность чисел. Метрика считается только после успешной проверки формата и полного совпадения ID со скрытыми ответами. Она вычисляется независимо от оценки, которую сообщил ML-модуль.

## Итоги текущего прогона

Windows, Python 3.12: **104 теста, 103 успешных и один пропуск** проверки настоящей символьной ссылки из-за прав ОС, 119,2 секунды. Эта проверка прошла на Linux. Проверены CatBoost, Parquet/TSV/CSV, числовые и строковые метки, вероятности, сохранность ID, резервный запуск без доступной LLM, ошибки API, бюджеты, остановка процессов и упаковка.

До проверки настоящего API полный ZIP был запущен на обеих демонстрационных задачах организаторов. Стартовый baseline и CatBoost обучались реально; вместо LLM использовался локальный сервер с командой finish. Итоговые файлы повторно проверены против исходных шаблонов, а входные файлы сверены по хешам.

| Регрессия | 22 449 | RMSE 59,7146 | RMSE 44,0241 | 173,3 с |
| Многоклассовая | 41 166 | Macro F1 0,0484 | Macro F1 0,6210 | 150,8 с |

Это оценки на фиксированной отложенной части train, не на скрытом test платформы. После выбора модели предсказания получены с полным переобучением. Дополнительное ограниченное сравнение Macro F1 early stopping и Balanced-весов не показало убедительного улучшения; проверенная конфигурация сохранена.

## Настоящий API и данные организаторов

Пользователь отдельно разрешил передачу обеих задач через `changellenge.up.railway.app`
с пределом 80 000 токенов на задачу и 160 000 суммарно. Выполнены два прогона
каждой задачи. Первый выявил потерю обученной модели при нехватке времени на
полный refit: классификация осталась с Dummy-оценкой 0,0484. Это исправлено.
Теперь проверенная модель сохраняется до refit и остаётся доступной при его сбое.
Успешный `run_backend` автоматически регистрирует кандидат, а старые обмены
удаляются из истории до отказа по токенному бюджету. Добавлены регрессионные тесты.

Повторный запуск использовал свежий ZIP исправленного кода и новые копии данных:

| Задача | Строк CSV | Holdout | Обучение | Время | Токены повторного запуска |
|---|---:|---:|---|---:|---:|
| Регрессия | 22 449 | RMSE 45,3354 | полный train | 138,1 с | 11 270 |
| Многоклассовая | 41 166 | Macro F1 0,6148 | полный train | 143,0 с | 31 429 |

Оба CLI завершились с кодом 0 и `success: true`. Причина `BudgetExceeded`
означает остановку перед следующим API-вызовом, когда его консервативное
резервирование уже не помещалось в заданный лимит. Проверенный CSV сохранён.
Разброс holdout-оценки между запусками связан с ограничением времени обучения;
это не оценка скрытого test платформы.

С учётом первого прогона: **56 148 токенов на регрессию, 61 741 на классификацию,
117 889 суммарно**. Превышений согласованных лимитов нет. Все восемь исходных
файлов повторного прогона совпали с оригиналами по SHA-256. Проверки CSV против
шаблонов прошли; ключ не найден в журналах. Локальные подробные отчёты находятся
в игнорируемых `.test-temp/final-e2e-report.json` и
`.test-temp/final-e2e2-report.json`; данные и журналы в Git/ZIP не включены.

Нативный ML-модуль поддерживает один табличный таргет и перечисленные в контракте метрики. Временное разбиение выбирается явно; групповой CV и нетабличные задачи требуют дополнительного кода через run_python. Возобновление после жёсткого завершения всего процесса не реализовано, но принятый CSV публикуется сразу.
